# SceneKit / ProcGen namespace map

Conceptual operation -> implementation (all deterministic; seeds where randomness exists).

| Concept | Call |
|---|---|
| world.inspect / measure / validate | `Scene:bounds()`, `Scene:counts()`, `Measure.*` (jump reach, `canJump(gap, rise, margin?, engine?)`, `airTime`, `profile(playerScale)`, door/ceiling/corridor clearance, `cameraClearance`, sightline, cover), `Validate.scene`, `Validate.penetration(a, b)` (oriented-box overlap depth) |
| terrain.generate / sculpt / carve / paint / smooth / biome / validate | `Terrain.heightmap`, `Terrain.sculpt`, `Terrain.flatten`, `Terrain.carve`, `Terrain.water`, `Terrain.paint` (height bands + slope), `Terrain.smooth`, `Terrain.validate`, `Terrain.toOps` -> `Apply.terrain` (checks every op first, one undo recording) |
| building.create / floor / wall / window / door / roof / stairs / trim / interior / decorate / validate | `Building.create` (returns per-storey walls, openings and rooms), `.floor` (holes), `.wall` (openings: door/window/gap), `.windowRun`, `.roof` (gable/shed/flat+parapet), `.stairs`, `.ramp`, `.railing`, `.column`, `.arch`, `.trim`, `.foundation`, `.subdivide`, `.decorate(scene, building, opts)` (seeded: one ceiling/wall light per room, neutral props via `alignToWall`/`distribute`, doorways, open sides and windows kept clear; `opts.sign` adds a placeholder sign above the front door) |
| model.inspect / scale / pivot / material / collision / optimize | `Model.inspect(scope)` (bounds, part/mesh/light counts, materials, anchored/collision summary, pivot offset from base centre, warnings), `Model.scale(scope, factor, { about })`, `Model.pivot(scope, "base_center" \| "center" \| CFrame)`, `Model.material(scope, { material, color, filter })`, `Model.collision(scope, { canCollide, canQuery, canTouch, collisionGroup, collisionFidelity })`, `Model.optimize(scope, { apply })` (report; opt-in safe fixes), `Model.apply(changes)`, `Model.revert(result)` |
| selection scope | Every `Model.*` op takes an Instance, a list of Instances or `Model.selection()` (Studio `Selection:Get()`; `{}` under Lune) |
| prop.place / scatter / align / snap / distribute | `Props.place`, `.scatter` (Poisson disc), `.alignToWall`, `.snap`, `.distribute` |
| lights / signs | `Props.light(scene, { pos, mount = "ceiling" \| "wall", normal, class, room, range, ... })` (non-colliding fixture part with a `light` spec -> PointLight/SpotLight/SurfaceLight child), `Props.sign(scene, { pos, normal, text })` (plate with a `sign` spec -> SurfaceGui + TextLabel; placeholder text such as `SIGN_A`); `Validate.scene` adds `light_placement` (class; range above 120 is an error (engine cap) and above 60 a warning; at most 4 lights and 1 shadow-casting light per room as warnings; fixture inside its room) and `sign_text` (non-empty) only when a scene has lights or signs |
| path / road / fence | `Paths.path`, `Paths.road` (kerbs), `Paths.fence` |
| vegetation.scatter / cluster / clear | `Vegetation.scatter` (noise density), `.cluster`, `.clear` |
| lighting.apply_profile / inspect | `Lighting.apply`, `Lighting.inspect`, `Lighting.blend`, `Lighting.audit` (15 presets named by function: lookdev_neutral, lookdev_contrast, bright_noon, overcast, golden_hour, blue_hour, night_clear, low_light, dense_fog, storm_dim, interior_warm, interior_cool, readability_max, perf_low, flat_capture; schema 1 ids still resolve; see [presentation](presentation.md)) |
| camera.frame / capture | `Camera.frame`, `Camera.captureSet` (front faces -Z) |
| scene.capture / compare / validate | Blender `render-manifest`, Studio `screen_capture`; `Scene.compare`; `Validate.scene` |
| layouts | `ProcGen.Dungeon/Cave/Arena/Settlement` -> `Placement.assign` -> `Validate.*` -> `SceneKit.Layout.toScene` |
| course.generate / validate / build | `ProcGen.Course.linear/tower/raceLoop/lanes/microArena` (or `Course.generate({ kind })`; course/1 manifest with segments, checkpoints, spawn, finish, hash) -> `ProcGen.Validate.course(course, rules)` (measured from geometry with the course's own jump profile) -> `Course.toScene(course, style?, { name? })` (ProcGen/CourseScene: pads, hazards, track pieces, gates, lanes, slots, arena floor and walls) |
| kit.validate / resolve / swap | `SceneKit/Kit`: `Kit.validate(kit)` (problems), `Kit.define(kit)` (frozen, raises), `Kit.placeholders(scene)` (specs with an `asset` attribute), `Kit.fit(piece, placeholder, fit)`, `Kit.resolve(kit, placeholders, { fit })` -> matches, missing, unused; `Apply.swap(root, kit, { load, fit, keepPlaceholders })` (Studio, one undo recording) |

Reversibility: `Apply.scene(scene, parent)` replaces the previous model of the same name by default (only if it carries `SceneKitHash`) inside one ChangeHistory recording; `{ replace = false }` keeps it; `{ dryRun = true }` returns counts and hash without creating anything. `Model.*` ops plan first: `{ dryRun = true }` returns the change list (`changes`: path, property, from, to) untouched; otherwise one recording (`Apply.withUndo`) wraps the apply, a failed set restores the earlier ones, and `Model.revert(result)` restores old values in Lune too. Values are computed in SceneKit (no `GetPivot`/`ScaleTo`) so Lune and Studio take the same path; pass `{ env = require("@lune/roblox") }` in Lune. `Model.scale` does not scale joint C0/C1 (it warns; use `Model:ScaleTo` for rigs).

Studio status: `Model.*`, light/sign instances and `Building.decorate` are specced in Lune on `@lune/roblox` instances (`tests/scenekit_model.spec.luau`, `tests/scenekit_dressing.spec.luau`) but not yet run in Studio; no fixture uses them, so fixture hashes are unchanged.

Previews: `factory.py render-manifest` takes `scene:manifest()` JSON directly; when the manifest has no `cameras` (only `tools/lune/build_fixtures.luau` adds them) it frames the part bounds as `Camera.captureSet` does. In Studio, `Camera.captureSet` returns plain `{x, y, z}` tables: wrap them in `Vector3.new` before `CFrame.lookAt` (skill `visual-qa`). Provenance: model attributes `SceneKitHash`, `SceneKitSeed`, `SceneKitStyle`, `Provenance`; parts carry `SceneKitId`, `Role` and `asset` placeholders for approved-asset swaps.

Player-scale constants: `Measure.ENGINE` (Roblox defaults) and `Measure.GUIDE` (level-design guidelines; override per game). `Measure.profile(playerScale)` gives the jump profile a course is built and validated with (a number scales the body; a table overrides `gravity`, `walkSpeed`, `jumpHeight`, `characterHeight`, `characterWidth`). `Measure.sightline` and `Measure.cameraClearance` read a Scene's `specs`, not a manifest's `parts` (skill `roblox-level-design-review` shows how to export Studio parts in that shape).

## Courses (ProcGen/Course)

Five generators share one manifest format (course/1) and one validator. Each takes `seed`, `difficultyCurve`, `segmentKinds` and `playerScale` plus its own options (module headers list them and their defaults):

| Kind | Builds | Checks (`Validate.course`) |
|---|---|---|
| `linear` | pads linked by gaps, steps, drops, beams, side jumps and hazards; a checkpoint every few challenges | jumpable_gaps, reachability, checkpoint_gating, checkpoint_spacing, difficulty_curve, landing_size, pad_overlap, headroom, hazard_placement, spawn_clearance |
| `tower` | pads spiralling round a core, one turn per floor, a checkpoint ending every floor but the top | the same as linear |
| `race_loop` | a closed centripetal Catmull-Rom track with width, grade and banking limits, gates (added so none are more than `maxGateSpacing` apart) and a start grid | loop_closed, min_turn_radius, max_grade, max_bank, track_clearance, gate_spacing, gate_coverage, grid_slots |
| `lanes` | equal-length lanes on a cell grid from a spawn edge to a base, with build slots beside each lane | lane_connectivity, lanes_disjoint, lane_balance, slot_balance, slot_access, lane_width |
| `micro_arena` | a round or square floor sized per player, a spawn ring, cover and hazards repeated per spawn sector; a hazard ring that cannot fit is reported in `course.dropped` | spawn_fairness, spawn_symmetry, spawn_separation, spawn_edge_clearance, area_per_player, spawn_clear, spawn_on_floor, piece_overlap |

Every kind also checks `course_hash`. Values are measured from the manifest (pad footprints, track samples), never read from the generator's notes, so a hand-edited course fails with the segment, the number and the limit. Limits marked "convention" in `CourseValidate.DEFAULTS` are level-design choices with a stated reason, not Roblox numbers. Jumps use `Measure.canJump` with the course's recorded profile; the engine numbers behind it are confirmed in Studio only by probe `lvl_course_run` (T3, pending until the owner runs it).

`Course.toScene` parts carry an `asset` attribute (a kit/1 piece key such as `course_platform`, `course_track`, `course_gate_post`, `course_floor_tile`) and the attributes GameKit binds to: `Checkpoint` (index), `SpawnSlot`, `Finish`, `Hazard` (`"kill"`), `Gate`, `BuildSlot`, `Lane`. `GameKit/Checkpoints.fromCourse(course)` turns the same manifest into a server-validated checkpoint run (skip, distance and minimum-time checks; `maxSpeed` defaults to the course profile's walk speed with slack, so vehicle courses pass their own `maxSpeed`), and the slices in `tests/gamekit_slices_world.spec.luau` drive a linear course and a lanes course end to end.

Micro-arena tiles cover the whole outline (every rim point lies on a kept tile), so on a round arena the outer square tiles reach up to one tile past the rim; with `edge = "wall"` that skirt is outside the wall. Fixtures: `course_linear`, `course_tower`, `course_race_loop`, `course_lanes`, `course_micro_arena` in `tools/lune/build_fixtures.luau`; previews with `python3 tools/blender/factory.py render-manifest build/fixtures/<name>.manifest.json build/previews`.

## Kit pieces (kit/1, SceneKit/Kit and Apply.swap)

A kit/1 manifest (contract in [runtime-kits.md](runtime-kits.md), section 9.5; G6 `factory.py kit` writes it) lists pieces with a key, a source (`procedural`, `blender_template:<template>` or `cc0:<source>:<id>`), bounds, pivot, materials, provenance, sockets, collision and triangle count. Any SceneKit spec or course part with an `asset` attribute is a placeholder for the piece with that key.

- Offline (Lune): `Kit.define(kit)` raises with every problem; `Kit.resolve(kit, Kit.placeholders(scene), { fit = "none" | "uniform" | "stretch" })` returns one match per placeholder (piece, scale, pivot offset in the placeholder's frame, size problems beyond `Kit.SIZE_TOLERANCE`), the placeholder keys with no piece and the pieces nothing used. Procedural pieces match but are flagged: SceneKit already built them.
- Studio: `Apply.swap(model, kit, { load = function(piece) return template end })` clones each piece onto its placeholder (bounds centred in X and Z, bottoms level, CFrame kept), copies the placeholder's name and attributes plus `KitId`, sets `CanCollide = false` for `collision = "none"`, and destroys or hides (`keepPlaceholders`) the placeholder, all in one ChangeHistory recording. The report lists `swapped`, `procedural`, `missing`, `failed`, `warnings` and `unused`. `fit = "stretch"` needs BasePart pieces; models scale uniformly.
- Status: Lune-specced (`tests/scenekit_kit.spec.luau`, and probe logic in `tests/gamekit_world_probes.spec.luau`); Studio behaviour is probe `lvl_kit_swap` (T3, pending). `SceneKit/Kit` is not exported by the `SceneKit` facade yet: require it directly.
